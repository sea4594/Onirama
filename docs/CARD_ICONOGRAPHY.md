# Card iconography (Phase 18)

Cards are designed to be identified by **silhouette and color**, not by visible text. All illustrations use local, resolution-independent SVG paths. A touch/long-press inspection and accessibility labels retain exact names and rules.

| Physical card | Face language |
| --- | --- |
| Four-color Locations | Existing Sun, Moon and Key, in brighter red, blue, green and amber-brown |
| Glyph Location | Diamond-shaped engraved rune (same four-color identity) |
| Crossroad | Multicolor border and its existing Location symbol |
| Colored Door | Arched portal and its hue |
| Door to the Oniverse | Portal and multicolor border |
| Nightmare | Fractured geometric dream shape, purple |
| Lost Dream | Trapped spirit, lavender |
| Happy Dream | Crescent and sparks, gold |
| Dead End | Blocked corridor, terracotta |
| Towers | Tower silhouette, actual printed edge markings and number |
| Sphinx, Diver, Confusion | Eye in a riddle, descent through waves, spiral |
| Denizens | Eight individual emblems (building, robot, squirrel, harpoon, hammer, color wheel, mirror, treasure); name retained below image |
| Dark Premonitions | Colored Door-count pips + Door silhouette + distinct consequence pictogram + existing live progress bar |
| Reserve Premonition pile | Blank violet card back, no visible title or card count; tap to inspect |
| Mirrors | Distinct Sun, Moon, Key, Glyph or color-marked mirror emblem; accessibility name retained |

**Sizing:** card motifs scale within their card's dimensions; the tiny face must not use a minimum icon size. Do not encode rules only in color: silhouettes/pip layouts differ. Preserve text in accessibility descriptions, inspect panels and external rules, not on physical card faces. Numbers intrinsic to Towers and live progress indicators remain necessary.

**Rules:** A drawn Door can be passed; it then goes to Limbo. Gaining one uses an eligible Key, prioritizing a normal color match before spending a Crossroad Key or an off-color Key through Chromatic Chaos. The player can select a particular eligible Key directly. Overload requires **sacrificing** a Dreamcatcher; ordinary Freeing remains a distinct action.
